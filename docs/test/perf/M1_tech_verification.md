## 4. 측정 조건의 한계 (SDD 3.12.4 요구)

- PC 1대에서 호스트와 봇이 CPU·메모리를 나눠 씀(봇이 가벼워 영향은 작지만 0은 아님).

- 참가자 FPS(NFR-012)는 측정 못 함: 참가자는 화면 없는 봇.
- 그래픽은 임시 도형이며 실제 애셋(식생·건물·캐릭터)이 아님. GPU·VRAM·메인 스레드 렌더 비용은 크게 늘 수 있음.
- 호스트는 움직이지 않는 상태(플레이어 조작·전투 없음), 봇 행동은 단순 자동 걷기.
- 다른 CPU(Intel·AMD) 결정론 확인과 실제 PC 8대 P8 판정은 M6-10에서 함.

## 7. 결론

**M1 기술 검증: 조건부 통과.** 호스트 서버 처리(평균 0.060 ms, p99 0.377 ms), 대역폭(호스트 1.03 Mbps, 참가자 175 kbps), 중도 참가(0.74 s), 메모리(1.4 GB / VRAM 1.4 GB)가 모두 기준을 크게 밑돌아 SDD 3.12.9의 미달 대응은 **대응 불필요, 관찰 항목**입니다. 「조건부」인 이유는 PC 1대·봇·임시 그래픽·직접 전송이라는 한계와 Steam 릴레이 접속 확인이 남아 있기 때문입니다.

M2 이후 권고:
1. 서버 틱 최악값(5.57 ms, AiApply 구간)을 관찰합니다. 흐름장 재계산 전용 `IPerfProbe` 표식을 추가해 원인을 확정합니다.
2. GC 할당(참가자별 생물 스냅샷)은 생물 수가 늘 때 다시 측정하고, 필요하면 풀링합니다.
3. 실제 애셋이 들어간 뒤 GPU·메인 스레드 예산을 다시 측정합니다(M2-12 UI, M6-10 8대 판정).
4. 사용자 수동: Steam 릴레이 접속 확인.

### 8.2 해석

- **60 FPS 고정은 vSync 상한 때문**이었습니다. vSync를 끄면 평균 454 FPS, 1% Low 176 FPS이고 GPU 프레임은 1.85 ms입니다. 호스트 GPU 여유가 큽니다. 다만 vSync를 끄면 GC 할당(1,283 KB/s)과 호스트 CPU(270%)는 프레임 수에 비례해 늘어 FPS 값은 참고용입니다.
- **업스케일을 꺼도 GPU 프레임 차이가 거의 없습니다**(4.82 vs 4.73 ms). 현재 그래픽이 임시 도형이라 DLSS 효과가 드러나지 않습니다. 실제 애셋이 들어간 뒤 다시 봐야 합니다. 업스케일을 끄면 VRAM이 약 190 MB 줄었습니다(1,417 vs 1,224 MB).
- **흐름장 재계산**은 평균 1.7~2.3 ms로 워커 예산 2.5 ms 안이지만 최대 3.1~4.6 ms로 가끔 넘습니다. 서버 틱 최악은 2.3~3.3 ms이고 상한 6.0 ms 이내라 R-41은 **관찰 유지**입니다. 이전 측정의 최악 5.57 ms는 이번 세 회차에서 재현되지 않았습니다.
- **Server.Total 정의 변경**: 이번 요약은 틱당 평균(틱이 있던 프레임만)이고, 2장의 0.060 ms는 틱 없는 프레임을 포함한 프레임당 값입니다. 틱당으로 환산하면 약 2배(0.116~0.135 ms)이며, 이번 요약의 프레임당 값(0.057/0.060 ms)은 2장과 일치합니다. 두 값을 직접 비교하지 않습니다. p99는 여전히 프레임 기준(초별 p99의 평균)입니다.

### 8.3 측정 조건 한계

- 1회차(225236)는 측정 중 유튜브 재생으로 GPU·FPS가 오염된 상태였습니다. 판정 항목(서버·대역폭·참가·메모리)은 영향이 작고 부하가 더해진 상태에서 통과한 것이므로 유효로 채택했습니다. 2·3회차는 영상을 끄고 측정했습니다.
- `M1_20261110_225837`, `M1_20261110_230435`는 측정 중 유튜브 재생으로 GPU·FPS가 오염돼 무효이며(후자는 3회차 중단) 이 보고서에서 쓰지 않습니다.
- 4장의 한계(같은 PC·직접 전송·임시 그래픽·정지 호스트)는 그대로입니다. 참가자 FPS와 다른 CPU 결정론은 여전히 측정하지 않았습니다.
